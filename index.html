A memory with a constitution

Continuity, with boundaries.

Everloom is designed around consent, provenance and an owner's final say. These are design principles. Their enforcement varies by implementation stage.

01

Capture with context

Record a fact alongside its source, scope, time and lifecycle. Keep uncertainty visible instead of turning guesses into history.

02

Share only when allowed

Agents should receive the smallest useful context, only under verified identity and explicit permissions.

03

Correct, revoke, restore

Surface conflicting edits, review an audit trail and recover from known-good backups rather than silently replacing truth.

Create with source

A fact is recorded together with where it came from, its scope, the time and its lifecycle. Uncertainty stays visible instead of a guess quietly becoming history.

  • Source and time travel with the fact
  • Guesses are labelled as guesses

Classify and scope

Each memory belongs to an owner and carries a classification. The private vault is a separate class that stays on the device and out of routine pull, search and handoff.

  • Owner and classification are set by the system, not claimed by a caller
  • Vault records have no ordinary cloud route

Use with permission

An agent should receive the smallest useful context, and only under a verified identity and an explicit grant. A grant scopes both the owner and the classification, and a mismatch is denied.

  • Grants can expire and can be revoked
  • Every decision is meant to leave an audit trail

Review and correct

When two edits disagree, both versions are kept and shown side by side for the owner to settle. Corrections are visible in the audit trail, and nothing is silently overwritten.

  • Conflicts are surfaced, not hidden
  • The owner has the final say

Forget or archive

The owner can ask for a memory to be forgotten or archived, and can restore from a known-good backup.

Retention, deletion and backup restore still need separate end-to-end acceptance tests before any production use.

System blueprint

Two homes. One owner.

The local device remains the center of gravity; cloud synchronization is a separately secured boundary, not a universal entitlement.

DEVICE

Private local memory

SQLite · search · provenance · offline work · local vault

Memory is kept on the device first, with its source and an audit trail, and it keeps working offline. The private vault is stored encrypted and stays here, outside routine sync.

⇄verified grants only
TRUST BOUNDARY

Authenticated sync layer

Owner binding · scopes · expiry · deny on mismatch

Identity is decided on the server side and never taken from the caller’s own request. Each grant is scoped to an owner and a classification, and anything that does not match is denied.

⇄non-vault records

A different way to see AI

Many people picture AI memory as something a company holds about them somewhere else. Everloom explores the opposite picture: memory is yours, like a document you keep, and an AI tool only borrows the part you choose to lend it.

  • Ownership. The owner decides where memory lives, who can read it and when it goes.
  • Consent. Access is explicit, scoped and able to be revoked.
  • Forgetting is a feature. A good memory can also correct itself and let go.
  • Plain claims. Everloom is bounded software. It does not make an AI conscious.

If the idea works, it could help people trust AI tools for the right reasons. That is an aim, and it needs evidence first.

    Questions worth asking

    Clarity is a feature.

    Can I store passwords or sensitive documents in Everloom today?

    No. The project remains a prototype. Do not entrust it with actual secrets or identity papers before a tested, approved secure release.

    Does the site collect or synchronize my demo memories?

    No. Its sample records and anything you type live only in JavaScript memory in this browser tab. Refreshing the page clears them. Your sound and motion choices are kept only in this tab’s session storage and clear when you close the tab.

    Does Everloom make an AI permanently conscious or continuously connected?

    No. It is software for bounded memory records and task handoff, not an always-on consciousness or a magical connection between providers.

    Where does my data ultimately belong?

    The design goal is to keep the owner in control of storage, permissions, export and deletion. Complete production guarantees still require testing.
